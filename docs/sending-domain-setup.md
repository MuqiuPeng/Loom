# Setting up a sending domain

Everything below is a step only you can do — buying a mailbox, editing DNS,
creating a password. The code side is already finished: the host is four lines
of `.env`, and nothing needs recompiling or redeploying.

Two commands do the verifying:

```bash
python -m loom.scripts.check_mail_setup    # DNS — run after step 3
python -m loom.scripts.send_test_email     # real send — run after step 4
```

---

## Step 0 — the one mistake that matters

**Do not put `From: you@robindev.org` on mail relayed through consumer Gmail.**

Google rewrites the envelope sender to your `@gmail.com` address and signs
`d=gmail.com`. Neither aligns with a `robindev.org` From header, so DMARC
fails on both legs — and no DNS record fixes it, because the failure is in the
envelope, not the zone. This configuration is *worse* than plainly sending as
`@gmail.com`, which today already passes SPF, DKIM and DMARC.

So: move the mailbox, or don't move the From header. Never one without the
other.

## Step 1 — pick a host

| Host | Price | `SMTP_HOST` |
|---|---|---|
| **Lark Mail** | **free** | `smtp.larksuite.com` |
| **Purelymail** | ~USD $10/yr | `smtp.purelymail.com` |
| **Migadu** (Micro) | ~USD $19/yr | `smtp.migadu.com` |
| **Fastmail** | ~USD $5/mo | `smtp.fastmail.com` |
| **Google Workspace** | ~AUD $10/mo | omit — also `smtp.gmail.com` |

They are equivalent for this pipeline. All you need is a mailbox that can send
over SMTP, receive over IMAP, and sign DKIM with your domain.

**Lark Mail is free and does all three.** Verified by connecting:

```
smtp.larksuite.com:587   STARTTLS advertised, handshake OK
smtp.larksuite.com:465   implicit SSL also available
imap.larksuite.com:993   * OK IMAP4 ready
```

Port 587 with STARTTLS is exactly what `mailer.py` already does, and
`inbox.py` derives the IMAP host on its own, so Lark needs no code change at
all. Sign up at larksuite.com (the international product), not feishu.cn —
the China edition is a separate org and its mail service expects a Chinese
business registration.

Two Lark-specific steps that are easy to miss, because SMTP is off until you
do both:

1. **The admin has to allow third-party clients.** Lark gates IMAP/SMTP behind
   an org setting — Admin → Mail → allow members to use third-party email
   clients. You are your own admin here, but the toggle still has to be found.
2. **SMTP uses a separately generated password, not your Lark password.** Lark
   shows a random one when you set up a client, in the same shape as a Gmail
   app password. That string is what goes in `SMTP_PASSWORD`.

Two things to check for yourself before committing to it: whether Lark's terms
permit cold commercial outreach (it is a mailbox service rather than a bulk
ESP, so it sits with Workspace rather than SendGrid, but read it), and how its
outbound reputation lands with Gmail, which is what most Australian small
businesses actually read their mail in.

**What you do NOT want:** SendGrid, Postmark, Mailgun, SES. Their terms all
require permission-based lists; cold outreach violates them, and an ESP
suspension is faster and more total than a Gmail throttle.

**Also not available**, in case you go looking: G Suite legacy free edition
closed to new signups in December 2012, Zoho's free tier dropped SMTP, and
Cloudflare Email Routing forwards inbound only.

## Step 2 — create one mailbox

One address is enough. Something a stranger reads as a person:
`robin@robindev.org`.

Avoid `info@`, `hello@`, `noreply@`. The first two read as a company that
isn't one; the third is on Loom's own refuse-to-send list.

---

## Step 3 — DNS, at Cloudflare

`robindev.org` is on Cloudflare (`surina`/`ryan.ns.cloudflare.com`), so this is
the DNS tab of that dashboard. Four records.

Your host's setup page shows the exact values for the first two — use theirs,
not anything from memory. Set **Proxy status: DNS only** (grey cloud) on all
of them; mail must not be proxied.

**1. MX** — from your host. Shapes seen in the wild:

```
Lark Mail          1  mx1.larksuite.com
                   5  mx2.larksuite.com
                  10  mx3.larksuite.com
Google Workspace   1  smtp.google.com
Migadu            10  mx.migadu.com
Purelymail        50  mailserver.purelymail.com
```

**2. DKIM** — generated by your host, pasted verbatim. Usually a TXT record at
a selector like `google._domainkey` or `key1._domainkey`, sometimes a CNAME.

> **Lark does not include DKIM in its initial DNS list.** The records it shows
> during domain setup are verification, SPF and MX only. DKIM is a separate
> step in the admin panel after the domain verifies, and it is not optional:
> without it SPF is your only authentication, and SPF breaks the moment a
> recipient auto-forwards your mail somewhere else. Go and find it.

> **Google Workspace ships DKIM switched OFF.** Admin console → Apps → Google
> Workspace → Gmail → Authenticate email → Generate new record, then **Start
> authentication** after the DNS record is live. Skipping the second click is
> the most common way to believe you're signed when you aren't.

**3. SPF** — TXT record on the root (`@`). One record only; two is a permanent
error, and a permerror counts as no SPF at all.

```
Lark Mail          v=spf1 +include:spf.onlarksuite.com -all
Google Workspace   v=spf1 include:_spf.google.com ~all
Migadu             v=spf1 include:spf.migadu.com ~all
Purelymail         v=spf1 include:_spf.purelymail.com ~all
```

Note Lark's include is `spf.onlarksuite.com`, not `spf.larksuite.com` —
the latter is a CDN alias with no SPF record on it at all. Lark's admin panel
gives you the exact string; paste that rather than anything typed from
memory, including the line above.

Lark also specifies `-all` where the others use `~all`. Follow Lark: with a
single sending path it is the stricter and correct choice. Revisit it only if
you ever add a second sender for this domain — a contact form, a newsletter
tool — because `-all` hard-rejects anything not in the include.

**4. DMARC** — TXT record at `_dmarc`.

```
v=DMARC1; p=none; rua=mailto:dmarc@robindev.org
```

`p=none` monitors without affecting delivery — correct while starting out.
**Do not omit `rua=`.** At tens of emails a day you are below the volume where
Gmail Postmaster Tools reports anything at all, so aggregate reports are the
*only* deliverability feedback that exists for you. They also surface the
alignment bug in step 0 if you hit it.

Then:

```bash
python -m loom.scripts.check_mail_setup robindev.org
```

DNS propagation is usually minutes on Cloudflare. If a record reads stale,
wait and re-run rather than editing it again.

## Step 4 — `.env`

```bash
SMTP_HOST=smtp.larksuite.com       # omit entirely for Google Workspace
SMTP_PORT=587
SMTP_ADDRESS=robin@robindev.org
SMTP_PASSWORD=<from your host>
OUTREACH_FROM_NAME=Robin Peng
```

The old `GMAIL_ADDRESS` / `GMAIL_APP_PASSWORD` still work as a fallback, so
nothing breaks if you leave them; `SMTP_*` wins when both are set. `IMAP_HOST`
is derived from `SMTP_HOST` automatically — set it only if your host is
unusual.

Also update the signature so the address in the body matches the From header:

```
config/email_templates.json  →  sender.email
```

Then restart so the reply poller picks up the new mailbox:

```bash
pm2 restart loom-api --update-env
```

`--update-env` is not optional. `load_dotenv()` does not override variables
already in the environment, so a plain restart keeps the old values with no
error to show for it.

## Step 5 — prove it, before writing to anyone

```bash
python -m loom.scripts.send_test_email
```

This sends one message to yourself through the same path the approved queue
uses, so a pass here means the queue works.

**Then open the message and read the source** — in Gmail, the ⋮ menu →
*Show original*. Find `Authentication-Results` and check:

```
spf=pass       smtp.mailfrom=robindev.org      ← your domain, not the relay's
dkim=pass      header.d=robindev.org           ← your domain
dmarc=pass     header.from=robindev.org
```

If `smtp.mailfrom` or `header.d` says anything other than your domain, you
have the step-0 problem: the From header moved but the relay didn't. **This
is the check that catches it. Nothing else does.**

---

## Step 6 — first fortnight

- Week 1: 5–10/day. Week 2: 15. Week 3+: 25–50. Weekdays, steady, never in
  bursts. Loom caps a run at 20 with a 30–90s gap regardless.
- Read replies. The signature undertakes removal within five business days,
  and the hourly poller only records what it finds — a person still has to
  answer.
- Watch `dmarc@robindev.org` for the first aggregate reports. They arrive
  daily from any receiver that saw your mail.

Do **not** buy a warm-up service. They work by having bot accounts mark mail
"not spam", which is squarely inside Google's written prohibition on using
multiple accounts to circumvent filters — and at this volume there is nothing
to warm anyway.

---

## Rolling back

Delete the four DNS records and drop the `SMTP_*` lines from `.env`. The
`GMAIL_*` fallback resumes and sending returns to `@gmail.com`, which is
authenticated and needs no configuration. Nothing in the code changes.
